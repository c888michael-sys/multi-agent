# Stages 2 & 3 — built without API keys

Built ahead of having real Gemini keys. Architecture and tests are locked; numeric defaults and prompt wording are explicitly placeholders to be tuned once keys arrive.

## What's in

### Stage 3 — Agents + Controller (`src/agents/`)

- `Agent` — stateless wrapper: applies a system prompt, calls the router. Used as a sub-agent.
- `Controller` — orchestrator with two modes (runtime flag):
  - **specialist**: controller calls the router once to pick the best sub-agent for the task, then dispatches.
  - **parallel**: all sub-agents run the task concurrently (`Promise.allSettled`), controller synthesizes via another router call. Failed sub-agents are recorded in the trace but don't block synthesis.
- `prompts.ts` — controller priming + routing prompt + synthesis prompt. Synthesis uses a `<<<id ... >>>` sentinel format instead of JSON to avoid parsing overhead at the model.
- Single-sub-agent parallel mode short-circuits the synthesis call (don't waste tokens synthesizing one thing).

### Stage 2 — Conservation + Visibility (`src/conservation.ts`, `src/pool.ts`)

- `ProviderPool` now supports two modes and per-provider call counters.
  - **round-robin** (default) — distributes load evenly across providers.
  - **serial** — drains one provider before touching the next. Keeps others fully reserved.
- `ConservationPolicy` watches the aggregate remaining-quota % and flips the router's mode with hysteresis (`thresholdPct` to switch to serial, `releasePct` to switch back). Manual `tick()` — no internal timer, so callers/tests stay in control.
- `formatUsageReport(router)` — pretty-prints per-provider state for a CLI/dashboard later.
- `Router` constructor now accepts `{ provider, estimatedDailyBudget }` entries. Without a budget, conservation is a no-op for that provider.

## What needs tuning once keys arrive

### Hard requirement: `estimatedDailyBudget` per account

Conservation mode does nothing useful until each provider has a budget estimate. Path:

1. Log into [aistudio.google.com](https://aistudio.google.com) per account, note real free-tier RPD (requests per day) for `gemini-3.5-flash`.
2. Set in `.env` or config: pass `{ provider, estimatedDailyBudget: <RPD> }` to `Router`.
3. If Google's numbers ever shift (they did in late 2025), update the budget number — no code change needed.

Note: this is a request-count budget, not a token-count budget. Free tier is capped by RPM/RPD primarily, not tokens. If you want token-accuracy later, the pool needs a `markSuccessTokens(index, tokens)` extension — straightforward, not implemented yet.

### Soft tuning

| Default | Where | When to revisit |
|--------|-------|-----------------|
| `thresholdPct: 25` | `ConservationConfig` | After running long jobs — if you find yourself in serial mode too often, lower it; if you run out of quota mid-job too often, raise it. |
| `releasePct: 50` | `ConservationConfig` | Should always be meaningfully higher than threshold to avoid flapping. 2x is a safe default. |
| `DEFAULT_COOLDOWN_MS = 60_000` | `src/pool.ts` | If Gemini sends `Retry-After` headers, this is unused. If it doesn't, calibrate against observed recovery time (per-minute limits = ~60s, per-day limits = ~24h). |
| `CONTROLLER_PRIMING` text | `src/agents/prompts.ts` | After first real runs — if Gemini ignores the "acknowledge uncertainty" framing, rewrite. Currently optimized for being short, not for being effective. |
| Routing prompt format | `prompts.ts: buildRoutingPrompt` | If 3.5 Flash picks "NONE" too often, or returns junk before the id, switch to a JSON-with-schema response and validate. Current parser just takes the first whitespace-delimited token. |
| Synthesis sentinel format `<<<id ... >>>` | `prompts.ts: buildSynthesisPrompt` | If the model echoes sentinels back into its synthesis or gets confused by them, switch to numbered headers (`## Agent 1`). |

### Things explicitly NOT done yet (waiting on real signal)

- Token-count tracking (vs request-count). Gemini's SDK returns `usageMetadata` on responses — easy to wire in when we have keys to see the shape.
- Stage 4 (local UI). Defer until the core proves itself in real use.
- Streaming responses. The current `complete()` is request/response only. Streaming is doable but the rotation semantics change (have to detect rate-limit mid-stream).
- Per-model routing in one router (e.g., "smart" vs "fast" tier). The `Provider` interface supports it but the Router doesn't yet route by tier.
