# UX trust & polish pass (v0.6)

Status: implementation-ready specification
Date: 16 July 2026
Target: local web UI
Priority: medium

## Decision summary

Four independently shippable phases addressing trust and polish gaps found in a 2026-07-16 UX review of the live app:

1. **Accessibility correctness** — a WCAG violation (focusable content inside an `aria-hidden` region) plus two ARIA gaps, all observed live in the running UI.
2. **Trust & recovery** — failed turns currently render as a fake `(error: ...)` reply with no retry path and no distinction between "quota exhausted" (recoverable, timing already known server-side) and a real failure.
3. **Artifact & Builder workflow polish** — the new review-first artifact workflow (see `docs/specs/2026-07-14-web-artifact-workflow.md`) has a needless interstitial, a flat unselectable file list, and state that silently vanishes on reload; Builder mode's tool activity is unreadable plain text.
4. **Conversation ergonomics** — threads are unlabeled, drafts die on reload, export is JSON-only, and a keyless first run gives no setup guidance.

## Why this is needed

The core chat, streaming, threads/files/goals drawers, command bar, theming, and the artifact review workflow are all live and functional (see README "Product audit" and `docs/specs/2026-07-14-web-artifact-workflow.md`). What's missing is the trust layer around failure and review — a user who hits a rate limit, opens the file-review dialog, or reloads mid-session currently gets a worse experience than the underlying system actually supports.

## Non-goals

- Provider attribution, the turn "flight recorder", and retry/edit/branch actions on **successful** turns — that is v0.5 Phase C (README, "UX/UI polish pass (v0.5)"). This plan's B2 retry button is scoped to **error turns only**; when v0.5 Phase C ships its turn-actions cluster, both should share one `.mm-turn-actions` styling block rather than duplicating it.
- Any change to the artifact service's safety model (validation, hashing, conflict handling) — Phase C here is presentation only, built entirely on the existing `/api/artifacts/*` endpoints from `docs/specs/2026-07-14-web-artifact-workflow.md`.
- Vendoring CDN dependencies, build tooling, or any change to the no-build frontend architecture.

## Phase A — accessibility correctness (frontend only, zero visual change)

- [x] **A1. `inert` on the closed settings drawer.** Observed live: the closed drawer keeps `aria-hidden="true"` while its buttons stay keyboard-tabbable (WCAG 4.1.2 — focusable content inside a hidden region). Only `SettingsDrawer` is affected: its scrim + aside stay mounted; `FileDrawer` / `ConversationDrawer` / `CommandBar` conditional-render and are fine. Fix: in `SettingsDrawer`, set the DOM property in an effect on the existing `drawerRef` plus a new scrim ref — `el.inert = !open` — keeping `aria-hidden={!open}` as is. Verify: from the idle page, Tab repeatedly — focus must never land on invisible settings controls; open settings and confirm every control is still reachable and Esc/scrim close still works.
- [x] **A2. Arrow-key navigation on the artifact review tablist.** `role="tablist"` without arrow-key support is an ARIA anti-pattern. In the tab row (`artifact-review.jsx:250`): roving tabindex (`tabIndex={tab === name ? 0 : -1}`), `onKeyDown` handling ArrowLeft/ArrowRight/Home/End (move selection + focus), and `id` / `aria-controls` pairing between each tab and the `role="tabpanel"` container. Verify keyboard-only: Tab lands on the active tab, arrows cycle Changes/Content/Preview, the panel follows.
- [x] **A3. Screen-reader status for streaming turns.** Tokens mutate a text node — silent for assistive tech. Add a `.mm-sr-only` visually-hidden utility to `style.css` and one `role="status"` `aria-live="polite"` element in `ChatTurn`, rendered for the newest turn only, announcing exactly two transitions: "generating reply…" when `entry.streaming` flips on; "reply ready" (or "turn failed") when it flips off. Do NOT make the bubble itself a live region — per-token announcements are unusable. Add `aria-busy={streaming}` to `.mm-turn-ai-bubble`. Verify with NVDA or Windows Narrator: one turn produces exactly two announcements.

## Phase B — trust & recovery: first-class error turns (server + frontend)

- [x] **B1. Typed SSE error events.** Today the stream's catch emits only `{ kind: "error", error: message }` (`server.ts:1333`) and the frontend fakes a reply with `(error: ...)` text (`app.jsx:5105`). (1) Server: add `errorName: err instanceof Error ? err.name : "Error"` to that event (additive; TDD — extend the existing resolver-error web test to assert `errorName: "AllProvidersExhaustedError"` streams through). (2) Frontend SSE loop: capture `evt.errorName`; classify `kind = (errorName === "AllProvidersExhaustedError" || errorName === "NoProvidersConfiguredError") ? "quota" : "provider"`. (3) Finalize: stop writing the fake reply — set `entry.error = { kind, message }` and keep `entry.text` as whatever partial actually streamed (may be empty). (4) Persist `error` through the `savePersistedStack` slim projection, defaulting absent on load (additive — old persisted entries render unchanged). All existing tests must pass.
- [x] **B2. Error card with retry.** In `ChatTurn`, when `entry.error && !streaming`, render a `.mm-turn-error-card` in the AI bubble area instead of an empty/fake reply: alert glyph, plain-language headline ("all free candidates for this route are cooling" for quota; "this turn failed — the reply was not generated" otherwise), the raw message inside a collapsed mono `<details>`, and a `↻ retry` button that re-submits `entry.prompt` through the normal submit path as a NEW turn (no history surgery). Disable retry while any turn is streaming, and when the entry had images that no longer exist in memory (`entry.imageCount > 0` but `entry.images` is empty after reload — base64 is never persisted). If partial text streamed before the failure, keep it visible above the card labeled "partial reply". Focus ring per v0.5 A2. Manual verify: devtools offline mid-turn → error card with working retry; reload → card persists and retry still works for text-only prompts.
- [x] **B3. Quota countdown + one-shot auto-retry.** For `entry.error.kind === "quota"` on the NEWEST turn only: poll `GET /api/usage.json` every 5 s while the card is visible; compute soonest recovery as the minimum positive `cooldownMsRemaining` across `roles[*].candidates` (fall back to the flat `providers` array if role data is missing); render `retries in ~m:ss` via the existing `formatCountdown` (:314), ticking locally between polls. An `auto-retry` toggle on the card (default ON, state per entry, not global) fires the retry ONCE when the countdown reaches zero AND `document.visibilityState === "visible"` — it never loops; a second failure re-renders the card with auto-retry off. Note: the router already absorbs waits ≤ 60 s (`maxRetryWaitMs`), so this path only triggers for longer cooldowns. Manual verify: with a single low-RPD key configured, burn the quota, confirm the countdown matches the sidebar gauge and exactly one automatic resubmit fires.

## Phase C — artifact & Builder workflow polish

- [x] **C1. Auto-prepared review (kill the interstitial).** `ArtifactReviewDialog` opens onto a "Destination folder (optional)" input + "Prepare review" button (:221–233) even though `prepare()` is local validation with no model call. Change: call `prepare()` automatically on mount with `basePath = ""`, showing a skeleton over the workspace while `phase === "validating"`. Move the destination affordance into the ready-state header: show the computed absolute `destination` with a `change folder` button revealing the input inline; confirming runs `resetProposal()` + `prepare(newBase)`. Validation failures land in the existing error state with the input still editable. An abandoned server-side proposal from a re-prepare simply expires — acceptable. Verify: dialog opens straight to the file list + diffs; changing folder revalidates; an invalid path (e.g. `../escape`) shows inline and is correctable.
- [x] **C2. Grouped file list + select all/none.** The original spec (`docs/specs/2026-07-14-web-artifact-workflow.md`) called for New/Modified/Unchanged grouping; the implementation renders a flat list (:239–248). Group `proposal.files` by `operation` (`create` / `update` / `unchanged` — `artifact-service.ts:119`) under sticky mini-headers `New (2)` / `Modified (1)` / `Unchanged (3)`, each header carrying a group checkbox (checked / indeterminate / unchecked; toggles its non-unchanged members), plus an `all / none` control in the list header over the whole selectable set. Unchanged rows keep disabled checkboxes; preserve existing row semantics (checkbox = selection, row button = `activeFileId`). Verify keyboard + mouse; the apply-bar count stays consistent throughout.
- [x] **C3. Richer artifact turn card + reload persistence.** Two gaps: the card says only "3 proposed files", and — because the slim projection drops `artifact` / `artifactReceipt` — the card, its applied/undone state, and the live undo window all vanish on reload. (1) Card (`ArtifactTurnCard` :20): show up to 4 file-path chips + `+N more`, the `artifact.projectName`, and after apply a live undo countdown from `receipt.undoExpiresAt` via `formatCountdown`, hiding the Undo button at expiry instead of letting the server reject it. (2) Persistence: extend the slim projection with `artifactSlim` (candidates as `{ path, bytes }` WITHOUT content — localStorage quota) plus the full `artifactReceipt` (the undo token is single-use, expires ≤ 10 min, and the server is loopback-bound — acceptable for a personal local tool; say so in the commit message). On load, rebuild the card from `artifactSlim`; `Review and save` needs full contents, so after a reload of a never-applied artifact disable it with title "full contents are only held until reload — re-ask the model to regenerate". Undo after reload works. Verify: apply → reload → card shows "Saved N files" + ticking countdown and undo works; never-applied artifact after reload shows chips + disabled review.
- [x] **C4. Open project files after apply.** After a successful apply, the dialog's complete-state footer and the applied turn card gain an `open project files` action — closes the dialog and opens the existing `FileDrawer` (thread a callback down from `HeroMindmap`, same pattern as the other drawer-open setters; the listing is already fresh via `setFileRefreshToken` :4788). Do NOT reuse the `preload` prop — it prefills the editor for the apply-edit flow, the wrong shape here. Verify: apply a 2-file artifact → click → drawer lists both files at the destination.
- [x] **C5. Builder live checklist.** Builder tool events render as the last 8 flat spans (accumulation `toolActivity.slice(-7)` :5067, display :1868–1874). Keep ALL events in the accumulator; derive a display model in `ChatTurn`: collapse `list_project` / `read_project_file` into one "inspected N file(s)" row, one row per `stage_file` path with ✓/✗ state, and a header `builder · N file(s) staged` that ticks up while streaming (spinner on the in-flight row). Cap visible rows at 12 with a `show all (N)` expander. Persist `toolActivity` through the slim projection (small strings; additive). Verify in Builder mode with a multi-file prompt: rows appear live, the counter ticks, reload preserves the finished checklist.

## Phase D — conversation ergonomics

- [x] **D1. Auto-titled threads.** Titles today are the truncated first prompt (`deriveSessionTitle`, `src/chat/session.ts`) unless manually renamed. After the FIRST completed turn of a session (`doneEvent.turns === 1`, skip if the turn errored), fire-and-forget from the SSE finalize: `POST /api/complete` `{ role: "action-repetitive", prompt: <title-instruction + user prompt + first ~400 chars of reply> }` → sanitize client-side (single line, strip surrounding quotes/trailing punctuation, ≤ 48 chars; reject empty or multi-sentence output) → `PATCH /api/sessions/:id` `{ title }`. Failures are silent (the derived title stands); the call must never block or delay the turn. Cost: one Cerebras call per new thread against the ~1M tok/day pool. The threads drawer refetches on open, so no extra wiring. Verify: new thread → one turn → threads drawer shows a concise generated title; a manual rename sticks (the PATCH only ever fires on turn 1).
- [x] **D2. Composer draft persistence.** A reload eats a long draft. Persist per session under `localStorage["lattice.draft.v1:" + sessionId]`, debounced ~300 ms where `draft` / `setDraft` live in `HeroMindmap`; restore on mount/session-switch only when the current draft is empty; clear on successful submit, on new-thread, and reject saved values > 8 KB. Attachments/images are NOT persisted (quota + staleness). Verify: type, reload, the draft returns; submit clears it; two threads keep separate drafts.
- [x] **D3. Markdown thread export.** JSON export exists (`exportSessionUi` :5430); add an `md` button next to `export` in the threads drawer row (:4391): fetch the full snapshot (`GET /api/sessions/:id`), walk the `history` parts (`user_text` / `model_text` — see `src/tools/types.ts` for the `ConversationPart` shape) into `# <title>` then alternating `## you` / `## orchestrator` sections with raw markdown bodies, image turns as `*[N image(s) attached]*`, and download via `Blob` + a temporary `<a download="<safe-title>.md">`. Pure frontend. Verify: a 3-turn thread with code blocks exports to a file that renders correctly in a markdown viewer.
- [x] **D4. First-run setup card.** With zero keys the server boots, the idle hero renders normal chrome, and the first turn just fails. In `IdleView`, using the same `useUsage` data as `SystemStatus` (:423): when `usage.providers` is a loaded-and-empty array, render a `.mm-setup-card` above the composer — "No providers configured — copy `.env.example` to `.env`, add `GEMINI_KEY_1` (free at aistudio.google.com/apikey), restart `npm run web`" — with the optional key families (`OPENROUTER_KEY`, `GROQ_KEY`, `MISTRAL_KEY`, `CEREBRAS_KEY`, `BRAVE_SEARCH_KEY`) as dim chips. Hide the card the moment providers exist; no dismiss state. Style per the v0.5 A6 `.mm-empty` pattern. Verify: rename `.env` away + restart → card appears and the composer still works; restore → card gone.

## Acceptance criteria (whole plan)

- No fake `(error: ...)` replies anywhere; failed turns show the error card with a working retry; quota failures on the newest turn show a ticking countdown and at most one auto-retry.
- Artifact review opens directly on the grouped, group-selectable file list; the turn card names files, counts down its undo window, and survives reload (undo included); Builder turns show a live staged-file checklist.
- Keyboard-only and screen-reader passes hold: no focusable content inside `aria-hidden` regions, arrow-key tablist, exactly two announcements per turn.
- New threads get generated titles; drafts survive reload; threads export to markdown; a keyless install explains setup on the idle screen.
- `npm run typecheck`, `npm test`, and the esbuild parse checks for `app.jsx` + `artifact-review.jsx` pass after every task; this file's checkbox flips `[x]` in the same commit that ships each task.
